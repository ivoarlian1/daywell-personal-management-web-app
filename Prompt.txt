## 3. TEKNOLOGI DAN ARSITEKTUR

Gunakan teknologi berikut selama kompatibel dengan kondisi proyek:

**Backend**
- Laravel versi stabil terbaru yang kompatibel dengan versi PHP yang tersedia.
- PHP dengan praktik penulisan kode yang mengikuti standar Laravel.
- Laravel Eloquent ORM.
- Laravel Form Requests untuk validasi.
- Laravel Policies dan Gates untuk otorisasi.
- Laravel Socialite untuk autentikasi Google.
- Laravel migrations, seeders, factories, dan automated tests.

**Frontend**
- Blade sebagai sistem template utama.
- Livewire untuk interaksi dinamis.
- Tailwind CSS untuk styling.
- Alpine.js untuk interaksi frontend ringan.
- Vite untuk pengelolaan aset frontend.

Gunakan versi dependensi yang kompatibel satu sama lain. Jangan mencampurkan API Tailwind CSS versi berbeda atau memasang paket yang tidak diperlukan.

**Database dan penyimpanan**
- Supabase PostgreSQL sebagai database utama.
- Supabase Storage untuk penyimpanan file jika memang diperlukan.
- Koneksi database melalui konfigurasi backend Laravel dan koneksi PostgreSQL yang sesuai.
- File privat harus dilindungi oleh mekanisme otorisasi yang benar.

**Integrasi**
- Google OAuth untuk login.
- Google Calendar API untuk integrasi jadwal.
- PDF generator yang kompatibel dengan lingkungan deployment.
- Progressive Web App (PWA).

**Deployment**
- Siapkan konfigurasi deployment yang terdokumentasi.
- Evaluasi apakah runtime Laravel, sesi, database, penyimpanan file, PDF generator, dan kebutuhan proses latar belakang benar-benar didukung oleh platform hosting yang dipilih.
- Jangan menganggap Vercel otomatis dapat menjalankan seluruh aplikasi Laravel secara konvensional.
- Jika deployment Laravel penuh tidak didukung oleh konfigurasi Vercel yang tersedia, gunakan hosting yang kompatibel dengan Laravel atau pisahkan fungsi deployment secara jelas.
- Jangan mengorbankan fungsi aplikasi hanya untuk mempertahankan satu platform hosting.

Jangan menampilkan kredensial, password, OAuth secret, service role key, atau token privat di frontend, repositori publik, maupun log.

## 10. INTEGRASI GOOGLE CALENDAR

Implementasikan integrasi Google Calendar melalui Google OAuth dan Google Calendar API.

Tahap awal harus berfokus pada sinkronisasi yang aman dan dapat diuji.

Fitur wajib:

- Menghubungkan akun Google.
- Meminta scope Google Calendar hanya ketika diperlukan.
- Menyimpan token sensitif secara aman.
- Menangani pembaruan access token menggunakan refresh token jika tersedia.
- Menampilkan status koneksi.
- Memilih kalender tujuan jika didukung.
- Mengirim jadwal aplikasi ke Google Calendar.
- Menyimpan ID event eksternal.
- Mencegah event ganda saat sinkronisasi diulang.
- Mencatat hasil sinkronisasi.
- Menangani kegagalan API dan pembatasan permintaan.
- Menyediakan opsi untuk memutuskan integrasi.

Mulailah dengan sinkronisasi satu arah dari aplikasi menuju Google Calendar. Jangan mengklaim sinkronisasi dua arah jika perubahan eksternal, konflik, penghapusan, dan pembaruan event belum ditangani serta diuji.

Jangan menghapus event eksternal secara diam-diam.

Sediakan status sinkronisasi seperti `pending`, `synced`, dan `failed`, atau rancangan setara yang konsisten.

Jika lingkungan mendukung antrean pekerjaan, gunakan queue untuk operasi sinkronisasi yang sesuai. Jika tidak, dokumentasikan alternatif yang aman.

Buat log yang membantu diagnosis tanpa membocorkan token atau informasi rahasia.

Uji hasil ekspor secara nyata, termasuk data panjang, karakter khusus, halaman banyak, dan kondisi tanpa data.

## 14. PROGRESSIVE WEB APP (PWA)

Siapkan aplikasi agar dapat dipasang sebagai PWA jika browser dan lingkungan mendukungnya.

Implementasikan:

- Web App Manifest.
- Nama aplikasi.
- Ikon aplikasi yang sesuai.
- Theme color.
- Tampilan saat dibuka sebagai aplikasi.
- Service worker.
- Strategi caching yang sesuai.
- Halaman fallback offline jika diperlukan.
- Dokumentasi cara menguji instalasi PWA.

Keamanan caching adalah persyaratan utama.

Jangan pernah menyimpan respons privat yang berisi Diary, Journal, Todo, Mood, token, profil, atau data pribadi lain ke cache publik secara sembarangan.

Jangan mengklaim aplikasi mendukung pembuatan dan sinkronisasi data secara offline jika mekanisme penyimpanan lokal, konflik, dan sinkronisasi belum benar-benar diimplementasikan serta diuji.

Jika dukungan offline penuh terlalu kompleks untuk tahap awal, prioritaskan PWA yang aman dan jelaskan batasan offline dengan jujur.

## 15. KEAMANAN APLIKASI

Terapkan keamanan sejak awal, bukan sebagai pekerjaan terakhir.

Persyaratan:

- Autentikasi untuk halaman privat.
- Otorisasi menggunakan Policies atau mekanisme setara.
- Pemeriksaan kepemilikan pada seluruh operasi baca, ubah, hapus, dan ekspor.
- Validasi input pada backend.
- Proteksi CSRF.
- Proteksi XSS dengan escaping yang benar.
- Pencegahan SQL injection menggunakan Eloquent atau parameterized queries.
- Rate limiting pada endpoint sensitif.
- Penanganan sesi yang aman.
- Pembatasan upload file berdasarkan tipe, ukuran, dan isi yang diperbolehkan.
- Perlindungan akses file privat.
- Perlindungan terhadap IDOR.
- Pengelolaan secret melalui environment variables.
- Tidak ada secret dalam repositori.
- Log tidak mengandung password, token, atau kredensial.
- Error produksi tidak menampilkan stack trace atau informasi internal.
- Kebijakan CORS dan security headers yang sesuai dengan arsitektur.
- Kebijakan penghapusan akun dan data yang jelas apabila fitur tersebut disediakan.

Jika menggunakan Supabase Storage, pastikan bucket dan kebijakan aksesnya sesuai dengan kebutuhan privat aplikasi. Jangan mengandalkan nama file yang sulit ditebak sebagai pengganti otorisasi.

Jika koneksi database langsung melalui Laravel digunakan, semua operasi database harus tetap melewati backend yang melakukan autentikasi dan otorisasi.

Jika Supabase Row Level Security (RLS) digunakan, rancang kebijakan dan konteks autentikasi secara eksplisit. Jangan menganggap RLS otomatis melindungi query backend yang menggunakan hak akses istimewa.

Buat `docs/security.md` yang menjelaskan kontrol keamanan dan risiko yang masih tersisa.

## 16. PENGUJIAN OTOMATIS

Buat automated tests menggunakan framework pengujian yang sesuai dengan versi Laravel.

Pengujian wajib mencakup:

### Autentikasi
- Halaman privat tidak dapat diakses tanpa login.
- Login valid berhasil.
- Login tidak valid ditangani dengan benar.
- Logout mengakhiri sesi.
- Alur OAuth ditangani dengan benar melalui pengujian yang sesuai.

### Isolasi data
- Pengguna A tidak dapat membaca data pengguna B.
- Pengguna A tidak dapat mengedit data pengguna B.
- Pengguna A tidak dapat menghapus data pengguna B.
- Pengguna A tidak dapat mengekspor data pengguna B.
- Manipulasi ID pada URL atau request tidak melewati otorisasi.

### CRUD modul
Uji operasi create, read, update, dan delete pada setiap modul.

### Integritas data
- Validasi form.
- Constraint unik habit log.
- Relasi Todo dan Scheduling.
- Validasi waktu jadwal.
- Validasi halaman buku.
- Penanganan tanggal dan zona waktu.
- Aturan status dan progres.

### PDF
- Endpoint ekspor memerlukan otorisasi.
- File PDF berhasil dihasilkan.
- Isi ekspor sesuai filter.
- Data antar pengguna tidak tercampur.

### Google Calendar
- Sinkronisasi sukses.
- Penanganan kegagalan API.
- Pencegahan event ganda.
- Penanganan token yang kedaluwarsa.
- Pencatatan status sinkronisasi.

Gunakan mock atau fake untuk layanan eksternal jika sesuai. Jangan mengklaim pengujian integrasi eksternal nyata berhasil apabila hanya menggunakan mock.

### PWA dan deployment
- Manifest dapat diakses.
- Service worker dapat didaftarkan.
- Aset penting dapat dimuat.
- Tidak ada cache publik yang membocorkan data privat.
- Konfigurasi produksi tidak mengandalkan file lokal sementara tanpa strategi penyimpanan yang sesuai.

Setelah membuat atau mengubah kode, jalankan pengujian yang relevan. Perbaiki error yang ditemukan dan jalankan ulang pengujian.

Catat perintah serta hasil aktual di `docs/testing.md`.

## 19. KRITERIA PENYELESAIAN AKHIR

Aplikasi hanya boleh dinyatakan selesai apabila seluruh kriteria berikut telah diverifikasi:

1. Aplikasi dapat dijalankan dengan prosedur instalasi yang terdokumentasi.
2. Koneksi database berfungsi.
3. Migration dapat dijalankan pada database target.
4. Autentikasi dan otorisasi berfungsi.
5. Seluruh modul utama memiliki operasi CRUD yang berfungsi.
6. Data tersimpan secara persisten.
7. Pengguna tidak dapat mengakses data pengguna lain.
8. Relasi Todo dan Scheduling berfungsi dengan benar.
9. Integrasi Google Calendar berfungsi sesuai cakupan yang benar-benar diimplementasikan.
10. Ekspor PDF pada modul yang relevan dapat menghasilkan dokumen yang valid.
11. PWA berfungsi sesuai batasan yang didokumentasikan.
12. Tampilan dapat digunakan pada desktop dan perangkat mobile.
13. Tombol dan formulir utama tidak berupa elemen dekoratif tanpa fungsi.
14. Validasi dan penanganan kesalahan diterapkan secara konsisten.
15. Pengujian otomatis yang relevan telah dijalankan.
16. Semua kegagalan pengujian yang diketahui telah diperbaiki atau dicatat secara eksplisit beserta alasannya.
17. Dokumentasi instalasi, konfigurasi, pengujian, keamanan, dan deployment tersedia.
18. Tidak ada kredensial nyata yang disimpan di repositori.
19. Tidak ada fitur yang dinyatakan berhasil tanpa verifikasi.
20. `docs/implementation-progress.md` mencerminkan kondisi proyek yang sebenarnya.

Jika ada kriteria yang belum terpenuhi, jangan menyatakan proyek selesai. Jelaskan bagian yang belum selesai dan lanjutkan pengerjaan jika memungkinkan.

## 20. INSTRUKSI EKSEKUSI TERAKHIR

Mulai sekarang dengan memeriksa seluruh workspace yang tersedia.

Setelah audit, buat atau perbarui dokumentasi arsitektur, desain database, roadmap, keamanan, deployment, testing, dan progres.

Kemudian langsung implementasikan proyek secara bertahap.

Setiap kali menyelesaikan suatu tahap:
1. Periksa hasil implementasi.
2. Jalankan pengujian yang relevan.
3. Perbaiki kesalahan yang ditemukan.
4. Perbarui dokumentasi progres.
5. Lanjutkan ke tahap berikutnya.

Jangan berhenti hanya karena satu modul telah selesai. Jangan hanya menampilkan daftar file yang perlu dibuat. Buat dan ubah file tersebut secara langsung di workspace.

Jika batas konteks, waktu, atau kemampuan eksekusi membuat seluruh proyek tidak dapat diselesaikan dalam satu sesi, simpan progres yang terperinci. Pada sesi berikutnya, baca `docs/implementation-progress.md`, periksa kondisi kode terkini, lalu lanjutkan dari pekerjaan nyata terakhir yang belum selesai.

**Prioritas utama adalah aplikasi yang berfungsi, aman, konsisten, dapat diuji, terdokumentasi, dan benar-benar siap digunakan — bukan sekadar banyaknya kode atau bagusnya tampilan.**

Mulai dengan audit workspace sekarang, lalu lanjutkan implementasi hingga kriteria penyelesaian akhir terpenuhi.
